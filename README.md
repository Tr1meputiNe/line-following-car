# 光电循迹小车（Arduino Uno）设计与制作

> 《Arduino 编程及应用开发》课程大作业

### 3.1 两个「反了」的坑（实测记录）

**扩展板丝印标的左右和实际是反的**，接线时按丝印接会导致转向反向。实测方法和结论：

| 实测方法 | 现象 | 结论 |
| --- | --- | --- |
| `bringup` 敲 `q`（代码让"左轮"变慢），看哪个物理轮子慢 | 左边那个慢 | **MOTOR-B(D9/D10) 驱动左轮，MOTOR-A(D5/D6) 驱动右轮** |
| `bringup` 敲 `r`，手指挡住车左侧传感器，看哪列数字变 | 右列数字变 | **左侧传感器实际接在 A0** |

所以代码里按实测写死，**和丝印不一致是正常的**。

### 3.2 为什么 D5/D6 和 D9/D10 这样分

- 每个轮子的两个脚放在**同一个定时器**上（D5/D6 = Timer0，D9/D10 = Timer1），两轮的 PWM 频率一致
- D4 用 `tone()` 只占 **Timer2**，不影响电机 PWM
- 12 个引脚互不重复，零冲突

### 3.3 接线表

#### ① 先把「地」连成一片（最容易忘的一步）

所有模块的 GND 必须连通。否则会出现：读数乱跳、电机不转、屏幕不亮。

```
Arduino GND ─┬─ MX1508 / 扩展板 GND
             ├─ OLED GND
             ├─ 左传感器 GND
             ├─ 右传感器 GND
             ├─ 启动按键的一端
             ├─ 两个 LED 的负极
             ├─ 蜂鸣器负极
             └─ 电池负极（如果用电池给电机供电）
```

#### ② 光电对管（两路接线完全一样，只是输出口不同）

```
发射管 IR333：  +5V ── R1(220Ω) ── 长脚(A) ── 短脚(K) ── GND

接收管 PT334：                    ┌── 集电极 C（长脚）
                  +5V ── R2(10kΩ) ─┤
                                  └── 输出 ──> A0（左）/ A1（右）

                 发射极 E（短脚） ── GND
```

| 从 | 到 |
| --- | --- |
| 左传感器输出 | **A0** |
| 右传感器输出 | **A1** |

> ⚠️ PT334 的 C / E 别接反。接反了不会烧，但读数会一直贴在 1023 不动。
> ⚠️ 发射管和接收管之间必须夹**黑色隔光片**，否则黑白读数会一样。

#### ③ 电机驱动 MX1508

| **GND** | 公共 GND | |

| **IN1** | **D5** | 右轮 前进 |
| **IN2** | **D6** | 右轮 反转 |
| **IN3** | **D9** | 左轮 前进 |
| **IN4** | **D10** | 左轮 反转 |
| **MOTOR-A（AO1/AO2）** | **右**电机两根线 | 接反了就两根线对调 |
| **MOTOR-B（BO1/BO2）** | **左**电机两根线 | 同上 |

> MX1508 没有单独的 PWM 脚和 STBY 脚，**调速直接用 `analogWrite` 打在 IN 脚上**。
> 有些板子丝印写成 `A1/A2/A3/A4`，对应关系一样。

#### ⑦ 供电（**本项目最关键的一环，见第九节**）

```
【推荐接法】
电池盒 / 充电宝 ──> MX1508 的 VM
Arduino ──USB──> 电脑 / 另一个充电宝
两边 GND 必须接在一起

【当前接法（有隐患）】
Arduino 的 5V ──> MX1508 的 VM
```

> ⚠️ **实测踩过的坑**：曾经出现过"电机突然停、过一会儿又好"的现象，
> 一度误判成"USV 供电被 500mA 保险丝限流"。后来**直接量 MX1508 的 VM 脚，发现只有 1V**
> —— 说明是 **5V 到 VM 这一段接触不良/断开**，电根本没送到电机，和电流能力无关。
> **教训：怀疑供电时，一定要量"用电设备那一端"（VM），不要只量电源那一端（Uno 5V）。**

## 四、传感器摆法与阈值标定

### 4.1 本车是「夹住线」的摆法

黑线夹在两个传感器**中间**，所以：

| 左 | 右 | 含义 |
| --- | --- | --- |
| **白** | **白** | **车正正压在线上**（正常状态） |
| 黑 | 白 | 线跑到车左边 → 车偏右 |
| 白 | 黑 | 线跑到车右边 → 车偏左 |
| 黑 | 黑 | 起始线 |

> ⚠️ **这一点非常关键，也是踩过的坑。** 代码最初把"两个都白"当成"丢线，按上次方向继续转" —— 但本车正常行驶时就是两个白，结果车一直在拐，**根本走不了直线**。现在"两个都白"是**直行**。
> 如果哪天换成"压在线上"的摆法（两个都黑才是正），这段逻辑必须跟着改。

### 4.2 实测阈值

| 状态 | 左传感器 | 右传感器 |
| --- | --- | --- |
| 黑线 | 941 ~ 949 | 915 ~ 926 |
| 白底 | 757 ~ 762 | 705 ~ 708 |

取两组之间的中间值：

```cpp
int threshold = 840;    // 读数 > 840 算黑线
int blackHigh = 1;      // 黑线读数大
```

余量：黑线最低 915 比 840 高 75，白底最高 762 比 840 低 78。实测噪声只有 ±2，非常稳。

**怎么自己重测**：`bringup` 敲 `r`，输出会带 `B`（黑线）/ `W`（白底）标记，5 秒一轮，正好够把车从白底滑到黑线上。

### 4.3 PPT 第 13 页思考题：R1 / R2 取值

> 本车用的是扩展板，R1/R2 已在板上焊好。下面是本题的解答，作为技术报告的理论部分。

**R1（发射管 IR333 限流电阻）**

```
R1 = (VCC - VF) / IF = (5 - 1.2) / 0.02 = 190 Ω
```

取标称值 **180Ω 或 220Ω**。220Ω 时 IF ≈ 17.3mA，发热小、寿命长，推荐。

**R2（接收管 PT334 负载电阻）**

输出 V_out ≈ I_C × R2，I_C 由反射光强决定。建议 **10kΩ 起**：

| 状态 | 期望 ADC 读数 |
| --- | --- |
| 黑线 | 900 以上 |
| 白底 | 150 以下 |

两组差值不到 100 → R2 取值不合适或者隔光没做好。

**最容易翻车的点**：发射管和接收管之间必须加**黑色隔光片**。否则红外光不经地面反射、直接从内部串过去，黑白读数会一样，怎么调阈值都没用。

**机械高度**：光电对管离地 **5 ~ 10mm** 最佳。

## 五、控制逻辑

### 5.1 循迹（`loop()` 第四步）

```cpp
int leftBlack  = leftValue  > threshold;   // 1 = 压到黑线
int rightBlack = rightValue > threshold;
```

| 左 | 右 | 判断 | 动作 |
| --- | --- | --- | --- |
| 白 | 白 | 车正 | 两轮都 `speedFast`，**直行** |
| 黑 | 白 | 车偏右 | 左轮**反转** `speedBack`，右轮 `speedTurn` |
| 白 | 黑 | 车偏左 | 左轮 `speedTurn`，右轮**反转** `speedBack` |
| 黑 | 黑 | 起始线 | 两轮直行，并开始判圈 |

**转向为什么用"内侧轮反转"**：外侧轮往前冲 + 内侧轮往后倒，车身几乎是原地转，这是双轮差速能做出最狠的转向。

> 每段代码都把 4 个脚写全（前进脚 + 反转脚），否则上一次转弯留下的反转会被带到下一段。

### 5.2 起步「踢一脚」（`startKickMs`）

直流减速电机**静止时的阻力比转动时大得多**，直接给 `speedFast` 经常原地不转（需要手推）。所以发车时先给满速 255 冲一下：

```
倒计时 3-2-1 → 满速 255 踢 150ms → 降回 speedFast=130 循迹
```

### 5.3 计时与判圈

计时**从起步的瞬间开始**：

```
按启动键 → 倒计时 → 满速踢一脚 → 立刻开始循迹，计时开始
        → 沿黑线跑 1 圈 → 再次压到起始线 → 停车显示成绩
```

> **没有"发车阶段"了。** 早期写法是先盲冲、等两个传感器**同时**压到起始线才进入循迹。
> 但两个传感器同时压到同一条黑带，要求黑带比两个传感器的间距还宽，而且车横向只能偏 2~3mm，
> 实际几乎不可能满足 —— 结果是车永远进不了循迹，一直盲冲 5 秒后停住，看起来就是"压到线也不拐"。
> 现在起步就直接循迹，"双黑"只用来当**停车信号**。

**判圈 / 停车**：要求双黑**连续保持 `startLineMs`**，且已跑够 `lapMinMs`。

> `lapMinMs` 是防止"刚起步就误停"的保险：车摆在起始线**前面**时，起步一两秒就会压过一次起始线，
> 没有这个保险会立刻停住。若车是摆在起始线**后面**的引导线上，可以降到 2000。
>
> `startLineMs` 和起始线宽度直接相关：压线时间 = 线宽 ÷ 车速。
> 本车线宽 **3cm**、车速约 20~25cm/s，压线 120~150ms，所以取 **80ms** 留余量。
> **跑完一圈停不下来** → 降到 60；**弯道提前停车** → 加到 110。
>
> ⚠️ **如果车跑完一圈停不下来**，先量一下两个光电传感器的中心间距：
> 双黑要求 **起始线宽度 > 传感器间距**，且横向偏移在 `起始线宽/2 − 传感器间距/2` 以内。
> 3cm 的起始线配 25mm 间距，横向只剩 ±2.5mm，基本踩不中 —— 这时把起始线贴宽到 60~80mm。

## 七、两个程序的关键设计

### 7.1 字符串一律用 `F()`

AVR 上普通字符串**占 RAM**，`F("...")` 把它放进 Flash。

**为什么必须这样**：128×64 的 OLED 要在运行时 `malloc` **1024 字节**显存，而 Uno 只有 2048 字节 RAM。字符串占多了 `malloc` 就会失败，`oled.begin()` 直接返回 false，**屏幕一片黑，而且编译器不会报任何警告**。

| 程序 | 加 F() 前 | 加 F() 后 | + 显存 1024 |
| --- | --- | --- | --- |
| `main.cpp` | 690 | **544** | 1568 ✅ |
| `bringup.cpp` | 1246 | **544** | 1568 ✅ |

（`bringup.cpp` 加 F() 前是 1246 + 1024 = 2270 > 2048，**OLED 从来没初始化成功过**，这个坑排查了很久。）

### 7.2 OLED 刷新间隔不能太短

刷一次屏要往 I2C 发 1024 字节，实测约 **23ms**。这 23ms 里程序卡在 `display()`，**电机收不到新指令**（控制盲区）。

100ms 刷一次 = 每 100ms 有 23ms 盲走，车按 30cm/s 算会盲走 0.8cm，**占 3cm 线宽的四分之一**。
这个值做成了可调参数 `oledMs`（当前 100）。想减少控制盲区可以调到 250，代价是屏幕刷新变慢。

## 九、⚠️ 供电限制（本项目最大的瓶颈）

### 9.1 问题

两个直流减速电机**起步瞬间**的电流：

| 状态 | 单个电机电流（5V） |
| --- | --- |
| 空载转起来之后 | ~120mA |
| **堵转 / 刚通电还没转** | **~1000mA** |

**电机静止启动时状态就是堵转**，两个电机同时起步约 **2.2A**。

而 USB 供电路径只能给 **0.5A**（Uno 上有一颗 500mA 自恢复保险丝）。按 0.5A 算，电机端电压只有

```
0.5A × 2.25Ω ≈ 1.1V
```

**1.1V 只有额定扭矩的 20%，克服不了齿轮箱的静摩擦 —— 这就是"起步不动、推一下才走"的根本原因。**

推一下为什么有用：外力让转子转起来 → 反电动势建立 → 电流需求掉到 120mA → 供电轻松满足。

### 9.2 为什么自恢复保险丝越用越虚

polyfuse 每次跳闸，**常温阻值会永久性升高一点**。而它有个热惯性：电流刚超标的头一两百毫秒还没来得及跳闸，会放行一次超额电流 —— 我们的"踢一脚"就是在利用这个窗口。

**这个窗口很脆**：保险丝温热一点、线材换个细的、USB 口弱一点，窗口就关上了。表现出来就是"之前能跑、现在连抬起都不转"，而**等 5~10 分钟又好了**（保险丝冷却恢复）。

### 9.3 正反馈陷阱

```
电流更大 → 保险丝更烫 → 阻值更高 → 电机端电压更低
   ↑                                        ↓
   └──── 电机转不动 → 一直堵转 → 电流更大 ←──┘
```

所以**"加大力度"是错误的调参方向** —— 越加越死。本项目实测验证过：把 `startKickMs` 从 150 加到 300、`speedFast` 从 150 加到 200 之后，车反而连空载都不转了。

### 9.4 解法（比赛前必须做）

```
电池盒 4×AA (6V) 正极 ──> MX1508 的 VM
电池盒 负极 ──┬────────> MX1508 的 GND
              └────────> Arduino 的 GND     ← 必须共地！
Arduino ──USB──> 电脑 / 充电宝                  ← 只给板子供电
```

**电机的电走电池，板子的电走 USB，两边共地。** 改完之后：

- 待机画面的 `minV` 应该稳在 `4.9~5.4`（显示值），不再出现 2.x
- `rampStepMs` 可以调回 **5**，起步更利索
- 速度按 6V 重新标过：`speedFast = 110`（≈ 5V 下的 132），稳了再往上加
- 保险丝不再受冲击，不会越用越虚

> **没有电池盒也能做**：拿一根废 USB 线剪开（**红=5V，黑=GND**），
> 接到 MX1508 的 VM / GND，Arduino 另外插一路 USB，两边 GND 接一起。
> 充电宝能出 1~2A，比 Uno 那颗 500mA 保险丝强得多。

> **必须加的一颗电容**：470µF 以上电解电容并在 VM 与 GND 之间（正极接 VM，负极接 GND）。
> 它吸收电机换向的电流尖峰，是"电机一跑就复位"的标准解法之一。
> 再顺手给每个电机端子并一个 0.1µF 瓷片电容（焊在电机壳旁边）。

### 9.5 另一个绑定关系

只要电机还挂在 Uno 的保险丝后面，这两件事只能二选一：

- **要转向狠**（内侧轮反转）→ 换向是电流冲击最大的动作 → 中途可能停
- **要不停车**（内侧轮不反转）→ 转向明显变弱

接上电池之后就不用二选一了。

### 9.6 已确认的现象：起步一瞬间单片机复位

**实测现象**：按启动键 → 倒计时 → 车"冲一步"就停，**OLED 回到开机画面**（`Press START`），
而 MX1508 摸上去只是温的（不是过热保护）。

**⚠️ 不能用 `MCUSR` 判断**：Uno 的 bootloader（optiboot）会在跳到 sketch 之前把 `MCUSR` 清掉，
所以代码里读出来永远是 `0`（实测待机画面显示 `boot: 0`）。见
[optiboot issue #97 "MCUSR is cleared in bootloader"](https://github.com/Optiboot/optiboot/issues/97)。

**判据（实测可用）**：待机画面最后一行显示 `minV 起步值/稳态值` —— 两个都是**上一次运行期间的最低供电电压**。
放在 AVR 的 `.noinit` 段（复位不清 SRAM），所以**能跨过复位保留下来**。

**实测结果（最终确诊）**：

| 配置 | 屏幕显示 | 换算成真实电压 |
| --- | --- | --- |
| 一步跳到 255，踢 150ms | — | 冲一步就停 |
| 一步跳到 200，踢 100ms | `2.85/6.0` | 起步段 ≈2.66V |
| 软起动（5→200，每档 15ms） | `2.39/2.30` | 起步 ≈2.23V，**稳态 ≈2.15V** |

**两个值都塌**，而且稳态值是被真实写进去的（不是初始值 6.0）→ 这一趟确实跑过了 1 秒，
但整整一秒里电压都在 2.2V 上下。

> **结论：这不是"启动瞬间的电流冲击"，而是只要电机一转，供电轨就趴下。**
> 软起动、降 `speedKick`、加长斜坡全部无效 —— 问题不在启动策略，在**电机供电这条路上**。

**根因（已确认接线后确诊）**：`MX1508` 的 `VM` 接在 **Arduino 的 5V 引脚**上。
那颗 **500mA 自恢复保险丝**就串在电机回路里，而两个电机启动要 ~1A：

```
电流超标 -> 保险丝发热 -> 阻值暴涨 -> 电压塌到 2.2V -> 电流变小
   -> 保险丝慢慢冷却 -> 阻值回落 -> "又好了"
```

最后这一步正好解释项目早期那句"**电机突然不能用，过一会儿又好**"。
这不是接触不良，是这颗保险丝**设计上就带不动两个电机**。

> 采样从软起动**斜坡之后**才开始，所以 2.39V 这个数是正常行驶时测到的，不是斜坡打出来的。
> 读数用 AVR 内部 1.1V 基准反推，比真实值高约 7%（真实 5.0V 会显示成 5.36V）。

**推理链**（为什么能确定是单片机复位而不是程序判停）：

```
循迹循环只有两个出口：判圈（要求已跑够 lapMinMs = 5000ms）和 3 分钟超时
loop() 里没有任何 return
能让四个电机脚变成 0 的只有两处：setup() 和停车画面
=> 起步 5 秒内循环不可能退出，"冲一步就停"只能是 setup() 又跑了一遍，即单片机复位
```

**复位后为什么电压又回来了**：AVR 复位时所有 IO 变成高阻输入 → MX1508 输入悬空 → 电机停 →
负载消失 → 电压恢复 → 单片机正常启动。所以表现为"冲一步就停"而不是"一直瘫着"。

**根因（两个，都要治）**：

1. **供电塌陷**：起步"踢一脚"是全程电流最大的一瞬间（两个电机都堵转）。电机电源若取自
   Arduino 的 5V，这一下会把 5V 拉到 AVR 欠压复位阈值（约 2.7V）以下。
2. **电机电刷噪声**：直流电机换向器打火会通过电源线往 5V 里灌尖峰，
   [Pololu 的电机噪声应用笔记](https://www.pololu.com/docs/0J15/9)明确指出
   "large enough voltage dips can corrupt the data in microcontroller registers or cause the microcontroller to reset"。

**实测数据**：

| 起步方式 | 起步期间最低电压（屏幕显示值） | 结果 |
| --- | --- | --- |
| 一步跳到 255，踢 150ms | — | 冲一步就停 |
| 一步跳到 200，踢 100ms | **2.85V**（实际约 2.66V） | 仍然复位 |

2.66V 正好压在 ATmega328P 的 2.7V 欠压复位阈值之下 —— **欠压复位确诊**。

**软件缓解**：改成**软起动**，不再一步跳上去：

```cpp
for (int s = rampStep; s <= speedKick; s = s + rampStep) {   // 5,10,15,...200
  analogWrite(leftForward, s);  analogWrite(rightForward, s);
  delay(rampStepMs);                                          // 每档 15ms，共约 600ms
}
```

电机静止时是堵转、电流最大。慢慢升压能让它在"刚好转得起来"的电压上脱离静摩擦，
**那一刻的电流比一步给到 200 小得多**，供电才有机会撑住。

> 如果软起动之后还是复位，说明供电彻底不够，软件再没有余量了，只能做下面的硬件改造。

**硬件根治（按性价比排序）**：

| 做法 | 成本 | 效果 |
| --- | --- | --- |
| **电机电源单独走电池**（见 9.4），电源入口并 470µF 以上电解电容 | 一个电池盒 | **根治电流塌陷，本次问题的正解** |
| **电机端子并 0.1µF 瓷片电容**（每个电机一个，越靠近电机壳越好；有条件再加两个从端子到外壳） | 几毛钱 | 抑制电刷噪声，最常用最有效 |
| 电机线拧成麻花、远离信号线，尽量短 | 0 | 减少耦合 |

**根治**：见 9.4 —— 电池盒 → MX1508 的 VM，Arduino 单独走 USB，两边共地。

## 十一、整机调试流程

1. **烧 bringup**，按第十节逐项验完
2. **烧正式程序** `pio run -e uno -t upload`
3. **把车摆在赛道上**（对准方向）
4. **按启动键** → 倒计时 → 起步立刻循迹
5. 观察并对照下表调整：

| 现象 | 原因 | 改什么 |
| --- | --- | --- |
| 起步后不循迹、直接冲出去 | 转向没生效 / 传感器没看到线 | 看屏幕上的 `L=` `R=` 和 `WW/LB/RB` |
| 起步不转、要推 | 供电带不动堵转电流 | 见第九节 |
| 转向时中途停住 | 换向电流冲击 | 见 9.5；或改电池供电 |
| 跑完一圈停不下来 | 起始线不够宽，双黑没成立 | 见 5.3 的量间距说明；或 `startLineMs` 80 → 60 |
| 弯道提前停车 | `startLineMs` 偏小 | 80 → 120 |
| 直线上画龙 | 转向过头 | `speedBack` 60 → 40，`speedTurn` 135 → 125 |
| 转弯冲出去 | 转向不够 | `speedBack` 60 → 90，`speedTurn` 135 → 150 |
| 一直往一边偏 | 左右轮转速不一致 | 调 `trimLeft` |
| 压到线也不拐回来 | 先看屏幕上的调试信息 | 见 11.1，不用插电脑 |

> **一次只改一个参数**，改完跑 3 次再决定下一步。

### 11.1 跑完之后怎么"验尸"（`debugOled = 1`）

小车没法端着电脑跑，所以调试信息直接显示在 OLED 上。**跑的过程中**，计时下面是实时读数：

```
Running
00:12.34
L=920 R=760 LB        ← 左传感器 920(黑) 右传感器 760(白) → 程序判左转
[========        ]    ← 3 分钟进度条
```

**跑完（或冲出去撞停 / 超时）之后**，成绩画面会多出三行：

```
FINISHED!  time:
00:12.34
L 705-949             ← 左传感器这一趟读到过的【最小-最大】读数
R 710-762             ← 右传感器这一趟读到过的【最小-最大】读数
W120/L8/R0/B0         ← 四种情况各采样到多少次
```

第三行每 100 毫秒采样一次：`W`=两个都白(直行) `L`=左黑(左转) `R`=右黑(右转) `B`=双黑(起始线)。

> 开着 `debugOled` 时，成绩画面会**停 20 秒**，方便你走过去看；按一下启动键可以提前结束回到待机画面。

**怎么读**（阈值 `threshold = 840`，读数 **大于 840 算黑线**）：

| 屏幕显示 | 含义 | 下一步 |
| --- | --- | --- |
| `R 710-762`（最大值没超过 840） | **右传感器整趟都没见过黑线** —— 探头太高 / 线不够黑 / 线太细 | 用 `r` 重新测阈值，或降低探头高度 |
| `L 705-949` 且 `R 710-949` | 两个传感器都正常看到了黑线 | 传感器没问题，是控制/供电的问题 |
| `W` 很大、`L`/`R` 都是 0 | 车根本没压到线（方向偏了或者发车位置不对） | 调 `trimLeft`，或把车摆正 |
| `L` 和 `R` 都很大且来回跳 | 转向过冲、在画龙 | 降 `speedBack`、降 `speedFast` |
| `L` 大 `R` 一直是 0 | 只往一边偏（右轮偏慢） | 调 `trimLeft` |
| 有 `L`/`R` 但车不转 | 指令发了电机没执行 → 换向时供电塌了 / 某个通道反转不通 | 见第九节；用 bringup 的 `q` `w` 单独验反转 |

> 调试完把 `debugOled` 改回 `0`，成绩画面就会恢复成干净的"FINISHED + 时间 + press START again"。

## 十四、常见问题排查

| 现象 | 可能原因 |
| --- | --- |
| OLED 全黑 | 地址不对（试 `0x3D`）；SDA/SCL 接反；**字符串没用 `F()` 导致显存分配失败**（见 7.1） |
| 串口发字母没反应 | 烧的是正式程序，不是 `bringup`；或串口被别的程序占用 |
| 小车原地打转 | 左右传感器或左右电机接反（见 3.1） |
| 走不了直线、一直往一边拐 | **传感器是"夹住线"摆法，"两个都白"必须按"车正"处理**（见 4.1） |
| 第一个直角弯就停车 | `startLineMs` 太小 |
| 到起始线不停 | `startLineMs` 太大；或起始线太窄没同时盖住两个传感器 |
| 起步不转 / 推一下才走 | 供电带不动堵转电流（见第九节） |
| 跑一会儿突然停 | 保险丝热了，电压塌下去（见 9.2） |
| 白底黑线读数差不多 | 收发管之间没隔光；或 R2 取值不合适 |
| 电机不转但屏幕正常 | 电压卡在 3.5~4V：单片机够用、电机不够（见 9.1） |
| 蜂鸣器不响 | 引脚不是 D4，用 `bringup` 的 `z` 命令扫描确认 |
